# wai Phase 4 — Publication Readiness Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Everything needed to publish wai is ready and verified locally, except what only the owner can provide: licence, remote repository, signing certificates and Anthropic confirmation. That means:
- a macOS app bundle and DMG, plus a Windows installer built by CI;
- a release workflow and an opt-in update check;
- no way left to lose unsaved edits at quit;
- the first-party extensions;
- user and extension-author documentation;
- a final report listing exactly what the owner must do.

**Architecture:** No new subsystems.
- Packaging uses `cargo-packager` metadata in `crates/wai/Cargo.toml`.
- Releases come from a GitHub Actions workflow triggered by `v*` tags.
- The update check is a single HTTPS GET on launch when enabled.
- Hot-exit stores dirty buffers in `<config>/recovery/` from the quit hook.
- First-party extensions live under `extensions/` like `wai-waycarbon`.

**Tech Stack:**
- Existing crates.
- `cargo-packager` CLI: installed with `cargo install cargo-packager --locked`; MIT/Apache.
- `ureq` 2 with `rustls`, only for the update check. Check the licences and add only if no existing HTTP client is in the tree. Otherwise use the one GPUI already brings (`gpui-pre-http-client`/`reqwest`).

**Spec:** `docs/ESTUDO.md` §6, §10 Fase 4; roadmap Phase 4; phase reports `docs/RELATORIO-fase-{1,2,3}.md` (owner-only items, known gaps).

## Global Constraints

Everything in the roadmap, Phase 1–3 constraints and standing rulings still applies, plus the following.

**Bundle identity:**
- The bundle id is `app.wai.ide`, a placeholder the owner can change in one place: `crates/wai/Cargo.toml` `[package.metadata.packager]`.
- The app name is `wai`.
- When running from a bundle, notifications use the app's own identity, so the Terminal-identity borrowing is used only for unbundled dev runs.

**Signing and notarization:** every step reads secrets that do not exist yet: `APPLE_CERTIFICATE`, `APPLE_CERTIFICATE_PASSWORD`, `APPLE_ID`, `APPLE_TEAM_ID`, `APPLE_APP_PASSWORD`, `WINDOWS_CERTIFICATE`, `WINDOWS_CERTIFICATE_PASSWORD`. When a secret is absent the step is skipped, and the workflow still produces unsigned artifacts.

**Update check:**
- Off by default: setting `updates.check = false`.
- When on, it runs once per launch, with no background timer.
- It reads `https://api.github.com/repos/<owner>/<repo>/releases/latest`. The repo slug is a placeholder in settings; if it is unset, nothing is checked.
- It only shows a notice: `wai <version> is available` with "Open release page". It never downloads or installs anything.

**Hot-exit:**
- On any quit path GPUI reports (`on_app_quit`, which also runs on Dock quit and logout), dirty buffers are written to `<config>/recovery/<n>.json` as `{path, text, crlf, stamp}`.
- On the next launch they are restored as dirty tabs with the banner `Recovered unsaved changes`.
- Nothing is written into the original files.
- Recovery files are deleted when the tab is saved or discarded.

**First-party extensions:**
- They follow the same manifest/consent rules; nothing ships pre-enabled.
- `wai-navegador` is manifest-only: it contributes the Playwright MCP server via `npx`, which needs `process`.
- `wai-rotinas` runs only scripts from an allow-list file the user owns: `<config>/rotinas.toml`, with entries that are absolute paths and cannot be group/world-writable.
- `wai-remoto` is design + skeleton only; it does not listen anywhere in this phase.

**Docs:**
- English for README and guides.
- pt-BR for the owner report `docs/RELATORIO-final.md`.

## Review Focus

1. **Quit with unsaved edits through each path:** ⌘Q, window close, Dock quit, logout.
   - Expected: no edit is lost; Dock quit and logout go to recovery.
   - Owner: 4.0 test `dirty_buffers_are_recovered_after_quit`.
2. **Update check offline, rate-limited, with malformed JSON or a hostile release body.**
   - Expected: silent failure (logged only); text clamped; no auto-download.
   - Owner: 4.3 `update_check_handles_failures`.
3. **`wai-rotinas` given a script path that is relative, world-writable, or a symlink to such.**
   - Expected: refused with a clear message.
   - Owner: 4.4 `rotinas_refuses_unsafe_scripts`.
4. **Building the bundle on a clean checkout.**
   - Expected: `cargo packager --release` (macOS) produces `wai.app` and a DMG whose `Info.plist` carries the bundle id and version.
   - Owner: 4.1 verification step.
5. **The R57 residuals** (extension pane churn, list width, MCP PATH note).
   - Owner: 4.0.

### Task 4.0: Hot-exit recovery and Phase 3 residuals (R57)

**Files:**
- `crates/wai/src/editor/{recovery.rs (new),pane.rs,mod.rs}`;
- `crates/wai/src/workspace.rs`;
- `crates/wai/src/ext_panel.rs`.

**Behaviour:**
- **Hot-exit**, as described in the Global Constraints.
- **Pane churn:** extension-opened sessions reuse the pane of the previous extension-opened session of the same extension when it still exists, instead of adding panes. They never replace a pane showing a user-started session; when no pane is free, they open in the Open list only.
- **List width:** a `list` in a column inside a row gets a minimum width (e.g. 160 px) so a full-width sibling cannot squeeze it to 0.
- **MCP PATH:** document in `docs/extensions.md` (4.5) that bare MCP commands are resolved on wai's PATH. Nothing to code.

### Task 4.2: Release workflow

**Files:** `.github/workflows/release.yml`.

**Behaviour:**
- Trigger: `push` of tags `v*`.
- Jobs:
  - macOS (arm64): build, package app+dmg, sign and notarize when secrets exist;
  - Windows: build, package nsis, sign when secrets exist;
  - a final job creates a **draft** GitHub release with the artifacts and SHA-256 checksums.
- No secrets in logs.
- Validate the YAML locally. `actionlint` is optional if available; don't install heavy tools.

- [ ] **Step 1:** Write the workflow and validate the YAML; a dry-run is not possible without a remote.
- [ ] **Step 2:** Commit `chore: add release workflow`.
