# wai Phase 1 — Core MVP (macOS) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A native wai window opens a project folder. In it the user can:
- start, resume and close Claude sessions over ACP;
- chat with streaming markdown;
- answer permission requests with buttons;
- see tool calls, diffs and context usage;
- use an embedded terminal;
- get native notifications when a session needs them or finishes.

The layout and open sessions come back after a restart.

**Architecture:**
- `wai-agent`, a GPUI-free crate, wraps the ACP SDK in an actor on its own thread. It exposes wai's own domain types and an `async_channel` of `AgentEvent`s.
- `wai-terminal`, also GPUI-free, wraps `portable-pty` + `alacritty_terminal`.
- `wai-settings`, also GPUI-free, loads `settings.toml` and persists `state.json`.
- The `wai` binary crate owns every GPUI view and pumps the channels into entities with `cx.spawn` tasks. It never imports ACP types.

**Tech Stack:**
- `gpui-kit =0.9.0`, `agent-client-protocol 5` (feature `process`), `alacritty_terminal 0.26`, `portable-pty 0.9`;
- `smol 2`, `async-channel 2`, `serde`/`serde_json`/`toml`, `similar 3`, `notify-rust 4`, `base64`, `dirs 6`, `thiserror 2`.

**Spec:** `docs/ESTUDO.md`; roadmap `docs/superpowers/plans/2026-11-08-wai-roadmap.md` (Global Constraints and Review Focus apply). API knowledge: `docs/NOTES-gpui.md`, `docs/NOTES-acp.md`, `docs/spikes/S1-acp.md`, `docs/spikes/S2-ui.md`. Spike code for reference: `git show fase-0:spikes/s2-ui/src/main.rs` (terminal, editor, markdown streaming, tests) and `git show fase-0:spikes/s1-acp/src/main.rs` (ACP client).

## Global Constraints

Everything in the roadmap's Global Constraints applies, plus:

- **Lockfile pins.** `Cargo.lock` pins `taffy 0.15.0` and `unicode-properties 0.1.3` so that `gpui-kit/test-support` resolves.
  - Never run a bare `cargo update`. Use `cargo update -p <crate>`.
  - UI tests use `[dev-dependencies] gpui-kit = { workspace = true, features = ["test-support"] }`.
- **Test-module imports.** Test modules never `use super::*` under `use gpui_kit::*` (NOTES-gpui §17). Import `gpui_kit::prelude::*` and the named types.
- **Editors.** Every `EditorState` used for code uses `soft_wrap(false)`.
- **Caret blink.** It is configured once at startup: `CursorBlink::default().with_idle_timeout(Duration::from_secs(5))`.
- **ACP isolation.** Only `crates/wai-agent` depends on `agent-client-protocol`. Everything else uses `wai_agent::*` domain types.
- **No polling** in any crate:
  - background reads block on a `std::thread` and send through channels;
  - GPUI tasks drain channels and coalesce bursts with a `try_recv` loop before one `cx.notify()`.
- **UI copy** (English, exact):
  - status labels `Working`, `Needs you`, `Done`, `Error`;
  - preparing: `Preparing <agent>…`;
  - unauthenticated: `<agent> is not signed in. Open a terminal and run its login (for Claude: claude /login).`
- **Platform directories:**
  - config dir: `~/.config/wai` on macOS/Linux, `dirs::config_dir()/wai` on Windows;
  - state file: `<config dir>/state.json`.
- **Default settings:**
  - default agent `claude`;
  - command `npx -y @agentclientprotocol/claude-agent-acp@0.101.0`.

## Review Focus

These are the roadmap's five, each pinned to a task below:
1. Agent crash or missing agent → `Exited` with the stderr tail and a Restart action (Task 1.2 test `crash_mid_stream_reports_exit_with_stderr`, Task 1.6 view).
2. Unauthenticated agent → `AuthRequired` and the exact copy (Task 1.2 `require_auth_emits_auth_required`, Task 1.5 `auth_required_adds_notice`).
3. Huge tool output → the model keeps everything and the view shows 2,000 lines plus "Show all" (Task 1.2 `flood_tool_output_arrives_intact`, Task 1.5 `tool_output_truncated_after_2000_lines`).
4. Permission answered late → `BrokerError::Stale`, no panic (Task 1.2 `late_permission_answer_is_stale`).
5. No orphan agent processes after shutdown (Task 1.2 `shutdown_kills_agent_process`).

**Behaviour:**
- **Threading.** `spawn` starts a `std::thread` that runs `smol::block_on`. Inside it, `Client.v1()` with `connect_with(AcpAgent::from_str(&spec.command)?, actor_loop)`. `actor_loop` sends `initialize` (fs capabilities off), emits `Ready`, then serves commands until `shutdown` or until the command channel closes.
- **Prompts** use `prepare_request(..).on_receiving_result(..)` (or an equivalent non-blocking pattern) so several sessions can prompt at once. The `PromptRequest` result becomes `TurnEnded`.
- **Permissions.**
  - The handler stores the `Responder` in a broker map under a new id, emits `PermissionRequested`, and returns `Ok(())` at once.
  - `answer_permission` takes the responder out of the map and responds; an unknown id gives `Err(BrokerError::Stale)`.
  - At `TurnEnded`/`cancel`, pending responders of that session are answered `Cancelled` and `PermissionResolved` is emitted.
- **Auth.** An ACP `auth_required` error from `new_session`/`load_session` maps to `AgentError::AuthRequired` and also emits `AgentEvent::AuthRequired { agent: spec.name }`.
- **Exit.** When `connect_with` returns `Err(e)`, emit `Exited { error: Some(e.to_string()) }`; the SDK error already carries the stderr tail. A normal shutdown emits `Exited { error: None }`.
- **Content mapping.** Images become `ContentBlock::Image`; resources become `ContentBlock::ResourceLink` with a `file://` URI.

**Fake agent flags** (all optional):
- `--reply <text>` (default `Hello from fake agent`), sent as one chunk per word;
- `--chunk-delay-ms <n>` (default 0);
- `--ask-permission` (sends `ToolCall` kind Edit with `Diff{path:"notes.md", old:None, new:"hi\n"}`, then requests permission with AllowOnce/AllowAlways/RejectOnce, and replies `chose:<option_id>` or `chose:cancelled`);
- `--crash-after <n>` (after n chunks prints `fake agent crashed` to stderr and exits with code 3);
- `--require-auth` (`new_session` fails with the ACP auth-required error);
- `--flood <bytes>` (one ToolCall whose text content is that many bytes of `x\n` lines);
- `--sessions <n>` (`list_sessions` returns n sessions titled `Session <i>` with cwd `/tmp`, paged 10 per page);
- `--pid-file <path>` (writes its PID at start).

`load_session` replays `UserText("previous prompt")` then `AgentText("previous answer")`. Cancel stops the chunk loop and ends with `Cancelled`.
