# wai Phase 2 — IDE Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn the Phase 1 chat client into an IDE. The user can browse and search the project, open and edit files, review and revert every edit the agent made, answer the agent's questions, fork a session, start sessions from templates and see all agents at a glance. The Phase 1 residuals are hardened along the way.

**Architecture:** Same crates as Phase 1. New GPUI-free logic lives in new modules of existing crates, or in one new crate `wai-project` (file tree, search, watcher), so it stays unit-testable. The sidebar gains tabs (Sessions | Files | Search | Agents). A pane can now hold either a chat session or an editor with file tabs.

**Tech Stack:**
- `gpui-kit =0.9.0`, now with tree-sitter features: `tree-sitter-rust`, `tree-sitter-go`, `tree-sitter-typescript`, `tree-sitter-javascript`, `tree-sitter-json`, `tree-sitter-toml`, `tree-sitter-yaml`, `tree-sitter-python`, `tree-sitter-bash`, `tree-sitter-markdown`, `tree-sitter-css`, `tree-sitter-html`. Use whichever names gpui-kit actually exposes; drop the ones that don't exist and record that.
- `ignore 0.4`, `grep-regex 0.1`, `grep-searcher 0.1`, `notify 8`, `similar 2.7` (with timeout).
- `agent-client-protocol 5` with feature `unstable_session_fork`.

**Spec:** `docs/ESTUDO.md` §6, §8, §9. Roadmap: `docs/superpowers/plans/2026-11-08-wai-roadmap.md` (Phase 2 table and Global Constraints). Phase 1 outcome: `docs/RELATORIO-fase-1.md`. API knowledge: `docs/NOTES-gpui.md`, `docs/NOTES-acp.md`.

## Global Constraints

Everything in the roadmap Global Constraints and the Phase 1 plan Global Constraints still applies, plus:

- **No silent writes.** wai writes a file only on an explicit user action: Save, Revert, or Accept in a permission card (Accept lets the agent write). Revert refuses when the file on disk no longer equals the diff's `new_text`, and says so.
- **Project config cannot run code (ruling R15).** `.wai/` may define `theme`, `default_agent` (naming an agent the user defined), and templates. It may never define commands, shells or environment.
- **Diffs are bounded.** Every diff uses `similar` with a 200 ms deadline. Rendering stops at 2,000 diff lines with "Open file to see all".
- **Large files.** Files above 20 MB open read-only with a banner. Files above 200 MB are refused with "Too large to open in wai". Binary files (NUL in the first 8 KB) are refused with "Binary file".
- **Watchers.** One `notify` watcher per project, debounced in the watcher thread to at most one batch per 100 ms. It sends through a channel; no polling.
- **Search.** Runs on a background thread, respects `.gitignore`, streams results in batches, and is cancellable (a new query cancels the old one). Results are capped at 10,000 matches with "Showing first 10,000".
- **Tests.** No test reads the developer's home config, shell rc files or real Claude. Real-Claude checks live only in `#[ignore]` smoke tests.

## Review Focus

1. **A file changed on disk while open in the editor.**
   - Clean buffer: reloads silently.
   - Dirty buffer: shows "Changed on disk — Reload / Keep mine". Never overwrites without asking.
   - Owner: Task 2.4 test `external_change_reloads_clean_buffer_and_prompts_dirty`.
2. **Revert after the user (or the agent again) edited the file.** Refuse with "File changed since this edit — open it to compare"; never clobber. Owner: Task 2.5 test `revert_refuses_when_file_changed`.
3. **Huge or binary files from the tree, from search, or as attachments.** Refused or read-only per the constraints; the UI never freezes for more than 100 ms on open. Owner: Task 2.4 tests `binary_file_refused`, `large_file_read_only`.
4. **Very large repos** (100k files, node_modules ignored). Tree expansion is lazy, search streams, and the watcher does not blow up. Owner: Task 2.3 test `tree_lists_lazily_and_respects_gitignore`; Task 2.6 test `search_caps_and_cancels`.
5. **A question form the agent withdraws, or the turn being cancelled while the form is open.** The form resolves as cancelled without a panic; a late answer gives `Err(Stale)`. Owner: Task 2.1 test `late_question_answer_is_stale`.

// wai_agent
pub type QuestionId = u64;
pub struct QuestionRequest { pub id: QuestionId, pub session: SessionId, pub message: String, pub fields: Vec<QuestionField> }

### Task 2.9: Phase 1 residual hardening

**Files:** as needed in `crates/wai`, `crates/wai-terminal`.

**Behaviour:** each item below gets one test.
- **"Show all"** renders at most 20,000 lines; beyond that it shows "Open full output in editor", which opens a read-only scratch buffer.
- **Events that arrive before `new_session` returns** (title, usage, commands) are buffered per agent for that session id and replayed when the session lands (cap 1,000 events).
- **⌘W on a "Preparing…" pane** cancels the pending session: the session is closed when it lands, and it never appears in Open.
- **Terminal:**
  - scrollback of 10,000 lines with mouse-wheel scroll;
  - mouse selection plus ⌘C copy;
  - paste strips `\x03` in bracketed mode and turns CRLF into CR otherwise.
- **Clicking blank space in an already-focused pane** focuses its prompt when focus is elsewhere.
- **Quit order:** at quit, agents are signalled before the terminal is stopped.
