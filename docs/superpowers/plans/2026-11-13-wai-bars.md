# wai bars Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a bottom bar showing wai's MCP, stopped-extension, usage and version items. Let extensions put items in the top and bottom bars (API 1.3). Let the user hide items in all three bars and reorder the rail, kept in `state.json`.

**Architecture:**
- `wai-ext` gets `contributes.items`, the `bar` permission and two calls.
  - `item/update` goes through the same `Renders` coalescer as `panel/render`, now keyed by a panel-or-item slot.
  - `item/action` reports a click to the extension.
- `ExtHost` keeps each running process's item states and lists them as `BarItem`s.
- A new `crates/wai/src/bars.rs` (`impl Workspace`, like `topbar.rs`) holds:
  - the bottom bar;
  - wai's item texts, as pure functions of existing state;
  - the shared hide menu;
  - the rail order;
  - the extension item element.
- Hidden keys and the rail order are two new `AppState` fields.

**Tech Stack:** Rust, GPUI via gpui-kit / gpui-component 0.9 (`ContextMenuExt`, `PopupMenuItem::label`, `.checked`), serde (`state.json`), chrono (already a dependency, for the local clock time), the test binaries `wai-fake-ext` and `wai-fake-agent`.

**Spec:** `docs/superpowers/specs/2026-11-13-wai-bars-design.md` (binding; read it with this plan).

## Keys

Tasks 4–9 use these keys. The extension id never contains `/` (`ExtId` is `[a-z0-9-]`), so a key is unambiguous even when the item or panel id contains one.

| Bar | wai keys | Extension keys |
|---|---|---|
| Top | `wai.status`, `wai.palette`, `wai.terminal`, `wai.agents-toggle`, `wai.new-session` | `<ext id>/<item id>` |
| Rail | `wai.sessions` (cannot be hidden), `wai.files`, `wai.search`, `wai.agents` | `<ext id>/<panel id>` |
| Bottom | `wai.mcp`, `wai.extensions`, `wai.usage`, `wai.version` | `<ext id>/<item id>` |

## Review Focus

1. **A Settings check while the launch check is still running.** The newer run replaces the older one: dropping the older task kills its `claude` (`kill_on_drop`). The item and the open page both show the newer result. Test in Task 7.
2. **A `resetsAt` in milliseconds, or already in the past.**
   - A value above 10^12 is read as milliseconds.
   - A reset time at or before now is stale, and the item stays hidden.

   Tests in Task 8.
3. **An extension restarted by Open Folder.** Its items are not drawn until the new process sends `item/update` again. Test in Task 3.
4. **Hiding the icon of the selected sidebar panel**, an extension's as well as Files:
   - the sidebar switches to Sessions;
   - a main panel's pane stays open.

   Tests in Tasks 4 and 9.
5. **Stale and new rail keys.** A key in `rail_order` for an uninstalled extension is skipped. A newly installed extension's icon goes after the ordered ones. Pinned by `ordered`'s unit test in Task 4.
