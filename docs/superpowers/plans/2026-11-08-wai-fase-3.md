# wai Phase 3 — Extensions v1 + Windows Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** wai can be extended without touching its core.
- A manifest-only extension adds templates, commands, agents, MCP servers and Claude Code plugin suggestions.
- A process extension, written in any language, talks JSON-RPC over stdio and can draw declarative panels and act on sessions within the permissions the user approved.
- The first real extension is `wai-waycarbon`, written in Go.
- The code base is made Windows-ready: paths, PTY, keybindings, CI.

**Architecture:**
- A new GPUI-free crate, `wai-ext`, holds the manifest model, the installer, the permission model and the JSON-RPC host. Extension processes are children on their own threads, the same pattern as `wai-agent`.
- The `wai` binary renders extension panels as sidebar tabs from a declarative JSON tree, using gpui-component, and adds a command palette (⌘⇧P).
- Phase 2 residual data-safety fixes come first (ruling R42).

**Tech Stack:**
- Existing crates.
- `serde_json` for JSON-RPC 2.0, hand-rolled: about 150 lines, so no new RPC framework.
- `dunce 1` for Windows path normalization.
- gpui-component `command` (palette).
- Go 1.26 for `extensions/wai-waycarbon`, stdlib only.

**Spec:** `docs/ESTUDO.md` §6 (extensions: three layers, permissions, first extensions), §1 (decisions), §10. Roadmap Phase 3 table. Phase reports: `docs/RELATORIO-fase-1.md` and `docs/RELATORIO-fase-2.md`.

## Global Constraints

Everything in the roadmap, Phase 1 and Phase 2 constraints still applies, plus the following.

**Extensions are code the user chose to trust:**
- Installing shows every requested permission and needs explicit consent.
- A newly installed extension is disabled until consented.
- Nothing from a repository auto-installs.
- `.wai/` may *suggest* an extension (by id and source), and wai shows "This project suggests extension X", which the user must accept.

**Permission model (v1):**
- **Kinds:** `process` (run its own executable), `sessions:read`, `sessions:control` (open sessions, send prompts), `notify`, `panels`, `network` (declared, informational only in v1), `fs:<path>` (declared, informational only in v1).
- **Host-side checks:** every host→ext and ext→host call is checked against the granted set. A denied call returns JSON-RPC error `-32001` with the message `Permission denied: <permission>`.
- **Limits of v1:** `network` and `fs` cannot be enforced without a sandbox. The consent dialog says so plainly: `wai cannot restrict files or network access in this version; only install extensions you trust.`

**Extension-provided commands:**
- Agent commands and MCP server commands come only from installed and enabled extensions, never from `.wai/` (R15 still holds for project files).
- Claude Code plugins suggested by an extension are never installed silently. wai opens the terminal and types `claude plugin install <name>` without pressing Enter, so the user confirms by pressing Enter.

**Extension processes:**
- They are spawned from the neutral config dir (R18).
- They are restarted at most 3 times per session of wai, then marked `Crashed` with the stderr tail.
- They are killed on quit before the terminal stops.

**JSON-RPC limits:**
- Line-delimited JSON-RPC 2.0 over stdio, one message per line.
- Messages above 4 MB are rejected.
- At most 100 panel renders per second per extension; the excess is coalesced.

**Windows:**
- Every displayed or compared path goes through `dunce::simplified` (no `\\?\` prefixes shown or sent to agents).
- The terminal uses ConPTY via portable-pty.
- When the terminal is focused, `ctrl-c/v/n/w/o/q` go to the shell. App actions use `ctrl-shift-*` on Windows only in the Terminal context.

**CI:**
- `.github/workflows/ci.yml` must build and test on `windows-latest` and `macos-latest`.
- Windows-only code paths are unit-tested with pure functions that also run on macOS.
- Runtime Windows verification happens only in CI. It needs the owner's remote; record this in the report.

## Review Focus

1. **A malicious or buggy extension.**
   - It floods messages, sends huge payloads, never answers `initialize`, crashes in a loop, or calls APIs it was not granted.
   - Expected: the UI never blocks, limits hold, denied calls error, and crash loops stop at 3.
   - Owner: 3.3 tests `flood_is_coalesced`, `oversized_message_rejected`, `initialize_timeout_marks_failed`, `crash_loop_stops_after_three`, `ungranted_call_denied`.
2. **Install from a git URL with a hostile manifest.**
   - Cases: path traversal in `id`, a manifest that requests an executable outside its own folder, unknown fields.
   - Expected: rejected with a clear message.
   - Owner: 3.1 `manifest_rejects_bad_ids_and_paths`; 3.2 `install_refuses_escaping_paths`.
3. **Uninstalling an extension whose agent has open sessions.**
   - Expected: the sessions show the agent as exited and no orphan process is left.
   - Owner: 3.2 `uninstall_stops_processes`.
4. **Windows paths with the `\\?\` prefix, CRLF files, and ConPTY.**
   - Expected: nothing user-visible shows `\\?\`; CRLF files open and save without changing their line endings.
   - Owner: 3.7 tests.
5. **R42 residual races.**
   - Owner: 3.0 tests.

### Task 3.1: `wai-ext` manifest model

**Files:** `crates/wai-ext/{Cargo.toml,src/lib.rs,src/manifest.rs}`.

**Interfaces (Produces):**

```rust
pub struct Manifest { pub id: ExtId, pub name: String, pub version: String, pub description: Option<String>,
    pub contributes: Contributes, pub process: Option<ProcessSpec>, pub permissions: Vec<Permission> }
pub struct ExtId(String);                       // [a-z0-9][a-z0-9-]{0,62}, validated
pub struct Contributes { pub templates: Vec<wai_settings::Template>, pub commands: Vec<CommandSpec>,
    pub agents: Vec<AgentContribution>, pub mcp_servers: Vec<McpServerSpec>, pub claude_plugins: Vec<String>,
    pub panels: Vec<PanelSpec>, pub themes: Vec<String> }
pub struct CommandSpec { pub id: String, pub title: String, pub prompt: Option<String> } // prompt-only commands need no process
pub struct AgentContribution { pub name: String, pub command: String }   // path relative to the extension dir or a bare program name
pub struct McpServerSpec { pub name: String, pub command: String, pub args: Vec<String>, pub env: Vec<(String,String)> }
pub struct PanelSpec { pub id: String, pub title: String }
pub struct ProcessSpec { pub command: String, pub args: Vec<String> }
pub enum Permission { Process, SessionsRead, SessionsControl, Notify, Panels, Network, Fs(PathBuf) }
pub enum ManifestError { Parse(String), BadId(String), EscapingPath(String), MissingPermission(Permission), Unknown(String) }
pub fn parse_manifest(text: &str, ext_dir: &Path) -> Result<Manifest, ManifestError>;
```

**Rules:**
- TOML, `deny_unknown_fields`.
- A `process` section requires the `process` permission, and panels require `panels`.
- Relative executable paths must stay inside `ext_dir` after normalization (no `..`, no absolute paths unless they are bare program names found on PATH).
- `id` follows the regex above.

  - `parses_full_manifest`;
  - `manifest_rejects_bad_ids_and_paths` (cases: `../x`, `A_B`, `/bin/sh` as a relative command, a process without the permission);
  - `prompt_only_command_needs_no_process`;
  - `unknown_fields_rejected`.
- [ ] **Step 2–4:** RED → implement → gate.
- [ ] **Step 5:** Commit `feat: add extension manifest model`.

### Task 3.2: Install, consent, enable/disable, uninstall

**Files:** `crates/wai-ext/src/{store.rs,install.rs}`, `crates/wai/src/extensions_view.rs`, `crates/wai/src/workspace.rs` (an "Extensions" entry in the palette and the sidebar header menu).

**Interfaces (Produces):**

```rust
pub struct ExtStore { /* <config>/extensions/<id>/ + <config>/extensions.json (enabled + granted permissions) */ }
pub enum Source { Folder(PathBuf), Git { url: String, rev: Option<String> } }
impl ExtStore {
    pub fn open(config_dir: &Path) -> ExtStore;
    pub fn stage(&self, source: &Source) -> Result<Staged, InstallError>;   // copy or `git clone --depth 1` into a temp dir and parse the manifest; nothing enabled yet
    pub fn commit(&mut self, staged: Staged, granted: Vec<Permission>) -> Result<ExtId, InstallError>; // move into place, record consent
    pub fn list(&self) -> Vec<Installed>;
    pub fn set_enabled(&mut self, id: &ExtId, on: bool) -> std::io::Result<()>;
    pub fn uninstall(&mut self, id: &ExtId) -> std::io::Result<()>;
}
```

**Behaviour:**
- **Git:** runs `git` with a fixed argv: `git clone --depth 1 [--branch rev] -- <url> <tmp>`. The URL must be `https://` or `git@` and is never interpolated into a shell.

- **Extensions view:** lists the installed extensions with enable/disable and uninstall.
- **Uninstall:** stops processes first (Review Focus 3).
- **Project suggestions:** `.wai/extensions.toml` (`[[suggest]] id, source`) shows a dismissible notice and never installs.

### Task 3.3: Extension host (JSON-RPC over stdio)

**Files:** `crates/wai-ext/src/{rpc.rs,host.rs}`, plus a test fixture `crates/wai-ext/src/bin/wai-fake-ext.rs`.

**Protocol (v1, binding):**
- **Host → ext:**
  - `initialize {protocol: 1, wai_version, ext_id, granted: [..], project}` → `{panels?: [...]}`;
  - notifications `event/session_state {agent, session, state}` (needs `sessions:read`), `event/turn_ended {agent, session, reason}` (needs `sessions:read`), `event/file_saved {path}`;
  - `command/run {id}`;
  - `panel/action {panel, action_id, values}`.
- **Ext → host:**
  - `sessions/list` (needs `sessions:read`);
  - `sessions/open {agent?, prompt?, send: bool}` (needs `sessions:control`);
  - `sessions/prompt {agent, session, text}` (needs `sessions:control`);
  - `notify {title, body}` (needs `notify`);
  - `panel/render {panel, tree}` (needs `panels`).
- **Limits:**
  - `initialize` timeout of 10 s marks the extension `Failed`;
  - restart at most 3 times;
  - 4 MB message cap;
  - render coalescing.

**Interfaces (Produces):**

```rust
pub struct ExtHandle; pub enum ExtEvent { Ready { id: ExtId }, Render { panel: String, tree: serde_json::Value }, Notify { title: String, body: String },
    OpenSession { agent: Option<String>, prompt: Option<String>, send: bool, reply: oneshot }, Prompt { agent: String, session: String, text: String }, ListSessions { reply: oneshot },
    Crashed { id: ExtId, stderr_tail: String } }
impl ExtHandle { pub fn spawn(installed: &Installed) -> (ExtHandle, async_channel::Receiver<ExtEvent>); pub fn notify_event(&self, ev: HostEvent); pub fn run_command(&self, id: &str); pub fn panel_action(&self, panel: &str, action: &str, values: serde_json::Value); pub fn shutdown(&self); }
```

  - `oversized_message_rejected`;
  - `initialize_timeout_marks_failed`;
  - `crash_loop_stops_after_three`;

### Task 3.4: Declarative panels

**Files:** `crates/wai/src/ext_panel.rs`, sidebar tab integration.

**Schema (v1):** a tree of nodes `{type, id?, ...}`:

| `type` | Fields |
|---|---|
| `column` | `children` |
| `row` | `children` |
| `text` | `text`, `muted?` |
| `markdown` | `text` |
| `list` | `items: [{id, title, subtitle?, badge?}]`; clicking sends `panel/action` with `action_id = item id` |
| `button` | `id`, `label`, `style?: primary\|danger` |
| `input` | `id`, `placeholder` |
| `select` | `id`, `options` |
| `checkbox` | `id`, `label` |
| `badge` | `text` |
| `progress` | `value 0..1` |

- Unknown node types render as a muted `Unsupported element` line and never panic.
- Depth is limited to 32 and nodes to 2,000; beyond that the panel shows `Panel too large`.
- Form values (`input`, `select`, `checkbox`) are sent with any button action as `values {id: value}`.

### Task 3.5: Command palette and contributions wiring

**Files:** `crates/wai/src/palette.rs`, `workspace.rs`, `agents.rs`, `sidebar.rs`.

**Behaviour:**
- **Palette:** ⌘⇧P (`secondary-shift-p`) opens a gpui-component `Command` palette. It lists:
  - built-in actions (New session, Toggle terminal, Open folder, Search, Files, Agents, Extensions);
  - templates;
  - extension commands, where a prompt-only command starts a session with the prompt pre-filled and a process command sends `command/run`;
  - "New session with <agent>" for every agent (settings plus enabled extensions).
- **Extension agents:** they join the registry under the name `<ext-id>/<name>`, with the command resolved inside the extension dir.
- **MCP servers:** servers from enabled extensions are passed in `new_session` and `load_session` (`McpServer` stdio entries).
- **`claude_plugins`:** shown in the Extensions view as "Install in terminal". Clicking it opens the terminal and types the command without Enter.
- **Panels:** contributed panels become sidebar tabs after the built-in ones.
